CHANGELOG
=========

All notable changes to weewx-ecowittGateway are recorded here. Versions follow Semantic Versioning
(https://semver.org/).

[2.1.7] – unreleased
====================

Added
-----

- align in [[catchup]], off by default. Catchup records keep the time the device logged them at, and
  an Ecowitt device doesn't log on WeeWX's archive_interval boundaries: with a 5-minute interval a
  catchup could save a 13:17 record where WeeWX, running, would have saved 13:20. With align = true
  the records of each archive interval are combined into the record WeeWX would have made, at the
  end of the interval (13:17 becomes 13:20). A device logging more often than archive_interval has
  its records combined as a merged catchup does (averages, the highest gust and rain rate, the last
  rain total); one logging less often leaves gaps, and a warning says so. The interval still in
  progress is left to the loop packets. --catchup-dry-run shows the aligned records. Several
  gateways ([[sources]]) were already aligned. (Suggested by Johannes.)

Fixed
-----

- An early WH40 rain gauge, which sends no battery data, was reported as a low battery
  (rainBatteryStatus 1) over the HTTP API and as 1.6 V, OK, over the TCP API (GW2000A V3.3.3, WH40
  F214; the gateway's own page says Normal). Over the HTTP API it gives a level of 0 and no voltage
  in the live rain data; over the TCP API, a fixed 0x10. Both now give no value for wh40_batt,
  wh40_volt and rainBatteryStatus, and weectl device --sensors shows battery: --. A WH40 that gives
  a voltage, or a level other than 0, is unchanged. Over the TCP API a later WH40's battery byte is
  now read in 10 mV units (145 is 1.45 V), not 100 mV, as the GW1000 driver does following Ecowitt.
- lightningdettime an hour early for a strike in summer time, read in winter (issue #21, GW2000,
  Europe/Rome). The HTTP API gives the last strike's time as local time with no UTC offset, and for
  a strike on 17 August, read in November, the gateway gives it in standard time (19:27:30 for a
  strike at 20:27:30 CEST). time.mktime() read it with the date's own offset (CEST), an hour early.
  Where the gateway answers the TCP API (port 45000, as GW2000 and GW3000 gateways do), the time now
  comes from its UTC time, asked at startup and after each strike, not on every poll. Otherwise the
  HTTP time is read with the UTC offset in effect now. That is right in winter whether the gateway
  uses its current offset or always standard time; which one it does is still to be seen in summer.
- With a WH57 lightning sensor that hasn't detected a strike yet, Error processing distance: Could
  not convert '--.-' to a float was logged on every poll. Until the first strike the gateway gives
  --.- for the distance (and --/--/---- --:--:-- for the time); the distance is now left without a
  value, as the time already was, and nothing is logged. lightningcount and the other readings were
  not affected.

[2.1.6] – 17 November 2026
==========================

Fixed
-----

- A catchup from Ecowitt.net ended WeeWX with an AttributeError when Ecowitt.net answered "data": []
  (no data yet for the period, as just after midnight). Data that isn't an object, at any level, now
  gives no records.
- radiation from an Ecowitt.net catchup was 126.7 times too small (and illuminance too): the solar
  value Ecowitt.net gives in W/m² was taken as lux. It is now converted to lux, as the live data has
  it, and radiation worked out from that. Catchup from the SD card was not affected.

[2.1.5] – 16 November 2026
==========================

Fixed
-----

- The additions database kept every field of the archive record the station's database has no column
  for, including other extensions' fields (MQTT subscriptions, filepile …) a user had left out of
  the database on purpose. It now keeps only the driver's fields: those in its field map (with
  [[field_map_extensions]] names), gateway_online, and those WeeWX works out from them with
  [[Delta]]. [[additions]] extra_fields keeps named other fields too (all: every field, as before).
  Columns already added for other fields stay, but no longer fill.

[2.1.4] – 15 November 2026
==========================

Fixed
-----

- The standard columns (batteryStatus1, signal1 …) weren't used, and readings stayed under the
  driver's names (wn31_ch1_batt), when the field map settings repeated the default map (as an
  earlier version's full [[field_map]] does) or the station database had a column of the driver's
  name (an earlier version added it). A setting the same as the default no longer counts, and a
  field with a column of its own is kept and copied to the standard column. The station database's
  columns are read from the database first (its schema module isn't needed).
- weectl device --live-data showed values without a unit (batteryStatus1) as 0.000000.

Added
-----

- <sensor>_rssi: each sensor's received signal strength (dBm), beside <sensor>_sig (wh40_rssi,
  wn31_ch1_rssi …), as earlier versions had.
- runtime: how long the gateway has been running (seconds), as earlier versions had.
- weectl device --active-map lists the standard columns not used and why; --live-data says why when
  it shows a reading under the driver's name.

[2.1.3] – 15 November 2026
==========================

Fixed
-----

- With the gateway out of reach while WeeWX started, memory grew until the process was killed, and
  the gateway was polled more and more often (issue #11). Reading the gateway model for WeeWX's
  station information failed, so WeeWX built the engine again without shutting the first one down,
  and its collector thread went on polling into a queue nothing read; one more thread with each
  retry. The collectors now start when WeeWX runs the engine (the driver's first catchup or loop
  packet request; the service's STARTUP event), so a failed start leaves none behind; the model
  (hardware_name) is read once and gives the driver name if the gateway doesn't answer; and the
  collector queue holds at most 100 items, dropping the oldest.
- weectl device --live-data showed the driver's own names (wn31_ch1_batt) instead of the standard
  columns WeeWX records them in (batteryStatus1, rainBatteryStatus …), as weewx-ecowittGateway.py
  run directly already did.

[2.1.2] – 14 November 2026
==========================

Fixed
-----

- Installing over an earlier weewx-EcowittGateway extension recorded under another name left its
  extension record and weewx-EcowittGateway.py in place. The installer now finds the record by the
  file its installer installs, and removes a weewx-EcowittGateway.py left without its record.
- radiation is recorded by default, as well as illuminance: the gateway shows the light sensor as
  solar radiation (W/m²) or illuminance (lux), the same reading. The installer no longer asks
  (radiation_from_illuminance = False to turn it off), and weectl device --live-data shows radiation
  too.

Added
-----

- heap_free (the gateway's free memory), stationtype (firmware, eg GW3000B_V1.2.5), model, apName
  and the rain gains gain0 (tipping) and gain1–gain5 (piezo) in each loop packet, as earlier
  versions had. The text fields keep their last value in archive records (accumulator = firstlast).

[2.1.1] – 14 November 2026
==========================

Fixed
-----

- weectl device --sensors shows each sensor's rssi again, and the WH40's battery voltage (battery: 5
  (1.6V) (OK)).
- The WH40's battery voltage is recorded again, in wh40_volt.
- The WH68's battery voltage is recorded again, in wh68_volt (and the WS80's in ws80_volt). The HTTP
  API gives only a level for these, so they are read from the gateway's TCP API (port 45000) every 5
  minutes; if it doesn't answer, the log says so once.
- Catchup from the SD card: column names are matched whatever their case, so Indoor Temperature
  (inTemp) is backfilled; Feels Like (feelslike) and AQIN Temperature (co2_temp) were read into
  names the field map doesn't use and were never backfilled.

Added
-----

- weectl device --catchup-dry-run lists the SD card columns the catchup doesn't read, so a sensor
  whose column a gateway names in a way the driver doesn't know can be reported.

[2.1.0] – 14 November 2026
==========================

Added
-----

- Units in MQTT and ecwLoop.json field names: append_units_label = True in [[mqtt]] or [[loop_json]]
  adds each field's unit to its name (outTemp_C, windSpeed_mps, rain_mm), as the weewx-mqtt
  extension does; fields without a unit (outHumidity, windDir) keep their name. The label follows
  units. Off by default.
- Conventional names for other extensions' databases: when a database in [DataBindings] has a column
  such as p_dayRain, p_rainRate, hourRain, isRaining or lightning_last_det_time (DivumWX's
  divumwx_extras.sdb does), loop packets also carry the reading under that name, so the extension
  stores it; the driver's own field stays. Fields with a column in another extension's database
  aren't also stored in the additions database. [[additions]] [[[column_map]]] adds or changes
  names, other_bindings limits the bindings looked at.

Changed
-------

- The installer's additions database and ecwLoop.json questions say to answer n when a skin or
  extension such as DivumWX keeps its own; the README has a section on turning both off.

[2.0.0] – 12 November 2026
==========================

weewx-ecowittGateway is a WeeWX driver and service for Ecowitt gateways and consoles, built on Gary
Roderick's Ecowitt local HTTP API driver, ecowitt_http.py 0.1.0a28
(weewx-contrib/weewx-ecowitt_local_http (https://github.com/weewx-contrib/weewx-ecowitt_local_http),
commit 31bdfe5). This entry lists what it changes and adds to that driver.

Names, and installing over another driver
-----------------------------------------

- The driver is EcowittGateway: file bin/user/weewx-ecowittGateway.py, module
  user.weewx-ecowittGateway, section [EcowittGateway] of weewx.conf, extension weewx-ecowittGateway.
  Classes keep ecowitt_http.py's names (EcowittHttpDriver, EcowittHttpService …). [EcowittHttp] is
  still read if there is no [EcowittGateway] section.
- Installed over ecowitt_http.py, the installer moves [EcowittHttp] to [EcowittGateway], changes
  station_type and the service lists, and removes ecowitt_http.py and its extension record, keeping
  its settings and rain configuration.
- Installed over an earlier extension named weewx-EcowittGateway, the installer points driver and
  the service lists at the new module, removes the old file and extension record (on a
  case-insensitive file system, where they are the same file and record as the new ones, nothing is
  removed), moves the Ecowitt.net keys into [[catchup]], sets WeeWX's rule for rain from its
  rain_source setting, and offers to record radiation.

Added
-----

- Fields from current firmware: windDir10 (0x6D, 10-minute average wind direction), t_rain24 and
  p_rain24 (0x7C, 24-hour rain of each gauge), t_rainhour and p_rainhour (0x7D, the last hour's
  rain, which current firmware sends in place of 0x0F; in ecowitt_http.py these two fields were only
  filled by Ecowitt.net catchup, and 0x7D was logged as an unknown observation). Battery and signal
  fields for every sensor the gateway reports (ecowitt_http.py had none for the WH40, WH45/WH46,
  WH68, WS69, WS80, WS85 and WN35, nor for WH51 channels 9–16, nor signal for WH54 and WH55 channel
  4).
- Sensor map ([[sensor_map]]): multi-channel sensors (WN31, WN34, WN35, WH41, WH51, WH54, WH55) are
  reported on a fixed channel chosen by sensor ID, so re-pairing a sensor doesn't move its data to
  other WeeWX fields; it applies to loop packets, catchup records, the service and the command line
  (--no-sensor-map to see the gateway's channels). weectl device --sensor-map lists the paired
  sensors.
- Rain source: which gauge WeeWX rain/rainRate come from (tipping, piezo or none), configured the
  way ecowitt_http.py does it (WeeWX derives rain from that gauge's yearly total in [StdWXCalculate]
  [[Delta]]). The installer asks; weectl station reconfigure changes it. The driver logs a warning
  at startup if the rule names a total it doesn't produce (WeeWX's default without a rule is
  totalRain), which would leave rain empty.
- ecwLoop.json and MQTT ([[loop_json]], [[mqtt]]): written/published by the EcowittGatewayExport
  service, so each packet includes the fields WeeWX calculates, in driver and service mode alike.
  Off by default.
- GW1000 through the Ecowitt binary TCP API, with the same field names and units as the HTTP API
  (api = auto|http|tcp, tcp_port; weectl device --api). Catchup for a GW1000 uses Ecowitt.net.
- Installer: asks for the device address (checking it over HTTP or the TCP API), poll interval,
  driver/service/skip, other gateways to read as well (written to [[sources]]), rain source, catchup
  source and Ecowitt.net keys, sensor map (for each gateway), battery display, radiation, the
  additions database, loop_on_init, ecwLoop.json and MQTT. Every answer can come from an ECOWITT_*
  environment variable for unattended installs; a bad value stops the install before anything is
  changed. Without a terminal or variables it adds its settings and leaves the station driver
  unchanged.
- Several gateways ([[sources]], after the design of weewx-ecowitt-multi
  (https://github.com/mKainzbauer/weewx-ecowitt-multi) by mKainzbauer): each polled by its own
  thread and merged into one stream of loop packets by priority (source_priority, [[priority]],
  max_age). Running totals (rain, lightning and any other [[Delta]] input) are merged so WeeWX
  counts each rise once, keeping the part of a rise that comes after what was counted when another
  gateway takes over. After an outage of every gateway the driver restarts so catchup fills it
  (gap_mode, max_gap_wait, min_restart_interval); catchup combines and merges each gateway's
  history. Loop fields gateway_online_<name>; weectl device --sources and --source=NAME; debug =
  merge.
- [[limits]]: readings outside a minimum and maximum are dropped in loop packets, catchup records
  and the data the service adds.
- ignore_no_signal: a multi-channel sensor's readings are left out while its signal is 0.
- gateway_online loop field: 1 while the gateway is answering.
- radiation_from_illuminance: WeeWX radiation (W/m²) worked out from the light sensor's illuminance
  (lux) with Ecowitt's factor (126.7 lux per W/m²), so standard skins show it and WeeWX can work out
  ET.
- The additions database (EcowittAdditions service, [[additions]]): the fields of each archive
  record that the station's database has no column for are archived in ecowitt_additions.sdb, with a
  column (and daily summary) added for each the first time it has a value. Skins, Seasons included,
  use them by name like any other field (an xtype looks them up), or through the ecowitt_binding
  data binding. The installer asks (default yes, ECOWITT_ADDITIONS).
- Seasons skin columns: the standard columns the Seasons skin shows are filled from the fields with
  the same purpose: inTempBatteryStatus, outTempBatteryStatus, batteryStatus1–8 and signal1–8
  (WN31), lightning_distance, and from battery levels as 0 (OK) / 1 (low), rainBatteryStatus (WH40),
  hailBatteryStatus (WS90) and windBatteryStatus (WS80/85/90, WH68) ([[additions]]
  use_station_columns).
- pm2_5 is filled from the WH45/WH46 when there is no WH41/WH43 on channel 1, and co2 from a
  console's own CO2 sensor (co2_in) when there is no WH45/WH46.
- Air-quality fields: the 24-hour averages (co2_24h_avg, pm2_51_24h_avg–pm2_55_24h_avg,
  pm10_24h_avg), the WH45/WH46's AQIs (pm25_co2_real, pm25_co2_24h, pm10_co2_real …), its
  temperature and humidity (co2_temp, co2_humidity), the WH46's PM1.0 (pm1_0) and PM4.0 (pm4_0), and
  a console's own CO2 (co2_in) are mapped; the gateway reported them, but the field map left them
  out.
- Catchup: a warning when the records' interval differs from archive_interval, a summary after each
  catchup, [[catchup]] file_port for a device behind port forwarding.
- [Accumulator] entries made from the field map: counts (t_rain, p_rain, lightning_strike_count) are
  totalled; battery and signal states, running rain totals, the lightning count, distance and time,
  daymaxwind, windDir10 and 24-hour AQIs keep their last value. As the station driver, the installer
  and weectl station reconfigure remove entries other extensions added for names this driver never
  produces (only those still as they were added, and not fields in the field map settings), and
  correct a lightningcount entry of sum to last.
- Logging: long log lines split over numbered lines (syslog cuts longer messages off); the field
  map's size at debug = 1, the map at debug = 2; the active field map (the entries the gateway is
  filling) logged after the first poll; log_next_update.
- Command line (weectl device and the driver's own): --active-map, --sensor-map, --dump-api (every
  raw API response as JSON, masked), --sd-files, --catchup-dry-run, --sources, --source,
  --registered-only, --api.
- Documents: README, INSTALL.md (step-by-step and unattended installs), DEVELOPMENT.md, with
  plain-text copies (tools/md_to_txt.py).
- Tests (tests/, python3 -m pytest): the driver, service, installer and every command-line option
  against fake HTTP API and GW1000 gateways and a fake MQTT broker; a snapshot of the API parser's
  and the command-line tool's output (over 1,600 parser cases and 99 command-line runs). 321 tests
  in tests/ and 21 in Gary Roderick's suite pass (1 skipped).

Changed
-------

- Everything belonging to one gateway (settings, field map, collector thread, catchup, status) is in
  one class, GatewaySource; the driver and the service each have one, or one per gateway.
- The API parser is rewritten with shared helpers in place of a block of code per reading (39 KB
  instead of 190 KB), the command-line tool reads the device and reports errors in one place, and
  comments that only restated the code are gone. With everything added, the file is 577 KB against
  ecowitt_http.py's 651 KB.

Fixed in ecowitt_http.py 0.1.0a28
---------------------------------

Driver and catchup:

- WH45/WH46 data (co2, pm2_55, pm10_0 …) never reached WeeWX: the parser returned the sensor as a
  list, giving fields co2.0.<obs>; PM10 (and WH46 PM1/PM4) values were left as text.
- Catchup from Ecowitt.net stopped WeeWX at startup ('EcowittHttpDriver' object has no attribute
  'api_key'): the keys were never read. When it ran, its records had no readings (mapped to names
  the field map doesn't use), and its hourly and daily rain were the wrong way round. Its 24-hour
  rain wasn't converted to the station's units.
- SD card catchup failed when ip_address includes a port, stopped at a file on the card whose name
  isn't a year and month, ended at a connection lost while reading a file, and gave records a
  floating-point dateTime. [[catchup]] retries (and, with source = device, grace) were ignored; with
  source = either, an SD card failure stopped the catchup instead of falling back to Ecowitt.net.
- A response the driver couldn't parse, or an error during the daily firmware check, ended the
  collector thread, and the driver then waited for data for ever. When every attempt to reach the
  gateway timed out, the HTTP API failed with UnboundLocalError.
- While a gateway couldn't be reached, every poll logged errors although the service had turned
  failure logging off.
- t_rain, p_rain (and t_rainrate, p_rainrate) had no unit group, so WeeWX passed them through
  unconverted.
- The [Accumulator] entries named fields the driver never produces (lightning_distance for
  lightningdist …) and left others averaged (lightningcount, lightningdettime, the 24-hour AQIs,
  ws90_sig).
- The WS69 sensor array, which the API calls wh69, wasn't recognised in battery decoding or the
  sensor lists.
- An unreadable WH55 leak sensor voltage stopped all live data being parsed; an unreadable device
  time set rain_reset_day instead of time.
- Logging: with debug = collector every poll gave a logging error; the error for a live-data array
  that couldn't be processed was a logging error; the startup lines for the sensors, catchup and
  parser debug options showed other options' values; debug = "rain, wind" (one quoted string) turned
  nothing on; debug = loop never showed the packet time; the indoor sensor was called WH26.

Config editor (weectl station reconfigure):

- --no-prompt (or no terminal) failed with EOFError; with no rain gauge paired it failed with
  IndexError, and it stopped if the device couldn't be reached.
- Choosing none for the rain source left WeeWX calculating rain from the old gauge; any text
  containing part of a field name was accepted as the field; a missing [StdWXCalculate] or [[Delta]]
  raised KeyError.
- A new [EcowittGateway] section listed options the driver doesn't read.

Command line:

- weectl device failed on every command (--debug read under the wrong name); commands that contact
  the device failed with no --max-tries default; --sensors failed at the first field the driver
  didn't know, and with weectl device on registered_only; --default-map, --driver-map and
  --service-map failed, and the last two left a thread polling the device.
- --get-rain-data, --get-all-rain-data and --get-mulch-t-cal did nothing; --get-rain-totals failed
  without a rain gauge list, --get-rain-data when a total was missing, --get-services when a setting
  was missing.
- --sensors listed the WH57 twice and left out the WH51, the WH45/WH46 and any model not in its
  fixed list.
- The direct command line ignored debug in weewx.conf; --test-service ignored the station's settings
  other than the IP address.

Installer and code:

- WeeWX version numbers were compared as text (5.10 would have counted as older than 5.9).
- Regular expressions written as ordinary strings gave "invalid escape sequence" warnings under
  Python 3.12 and later.
